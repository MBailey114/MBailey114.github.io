AI-powered self-serve dashboards

Sky, 2025 – present · Built solo · Next.js, Python, custom MCP, OpenAI (GPT), OpenSearch

The problem

Non-technical users across Sky's departments relied on business analysts to file change requests against a fixed set of monitoring dashboards I'd owned for the previous three years. Turnaround could be days. The available set of views never quite matched what individual users actually wanted — so they either compromised or stopped asking.

Approach

I built a natural-language chat interface on top of the existing dashboard system. Users ask things like "show me 4G usage split by tech in a stacked bar chart over the last eight months"; a custom agent parses the intent, queries OpenSearch through a custom Model Context Protocol (MCP) server, and returns a chart widget. The user can add the chart to their own dashboard, resize it, and position it however they like. Over multiple queries they assemble a dashboard tailored to their own work — no change requests, no BA loop.

Why a custom agent orchestrator

Sky has an internal AI gateway that didn't support tool-calling in the form I needed. Rather than shoehorn my design into its limitations, I wrote a minimal orchestrator directly on top of the raw chat-completion API. The system runs on OpenAI's GPT models (chosen over Claude for cost) and the MCP layer stays cleanly separated — swapping providers later is a config change.

Stack

  • Frontend: Next.js, React, TypeScript. Chart rendering, drag-and-drop widget layout.
  • Agent layer: Python. Custom MCP server exposing data tools. Custom agent orchestrator on OpenAI GPT models.
  • Data: OpenSearch (the same data backbone as the pre-existing dashboards).
  • Middleware: GraphQL, reused from the existing dashboard stack.

Where it stands

Pre-rollout hardening. Demoed to three stakeholder groups so far: Sky's data engineering team, another Sky observability team, and a set of Comcast executives (Sky's parent company). The director is using the project as an anchor for a broader shift in the department toward agentic workflows — which has included me running onboarding sessions on effective and safe AI use across engineering and non-engineering work.

What I owned

  • The frontend UI and widget system
  • The custom MCP server and the agent orchestrator
  • Integration against OpenSearch and the existing GraphQL middleware
  • The demos and onboarding sessions driving adoption

Internal monitoring dashboards

Sky, 2022 – present · Next.js, React, GraphQL, OpenSearch, TypeScript

The problem

Multiple Sky departments needed visibility into operational data — telecoms usage, service health, platform metrics. Raw OpenSearch queries weren't practical for non-technical stakeholders; product teams and operations needed curated, reliable views they could lean on day-to-day.

Approach

Full-stack dashboards built iteratively with each department as a stakeholder. Next.js / React on the frontend, a typed GraphQL middleware layer, OpenSearch as the data backbone. The dashboards grew in scope over three years as more teams asked to be served by them.

Outcome

In active use across Sky. The dashboards became the launchpad for the AI self-serve work: the pain of the BA-mediated change-request process directly motivated building something users could steer themselves.
